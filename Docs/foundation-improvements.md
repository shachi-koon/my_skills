## 1. コーディングルールの位置づけ

**現状**: 基盤にコーディングルール専用の定義がない

**結論**: これは正しい設計判断
- コーディングルールはPJごとに異なる（TypeScript vs Python、React vs Vue等）
- 各PJの`.claude/CLAUDE.md`に追記する形で運用

**対応**: 現状維持（改修不要）

---

## 2. 企画・PJ立ち上げフェーズの追加

**現状**: 承認フローは「要件定義」から始まる

```
要件定義 → [承認①] → 非機能要件 → [承認②] → ...
```

**課題**: チーム開発では要件定義の前に以下が必要
- 企画・構想フェーズ（ビジネス目標、ROI検討、フィージビリティ）
- PJ立ち上げフェーズ（チーム編成、開発環境、コーディングルール策定、技術スタック選定）

**対応予定**:
- [ ] 企画フェーズ用のSkill追加
- [ ] PJ立ち上げフェーズ用のSkill追加
- [ ] 承認フローの拡張（承認⓪を追加？）

---

## 3. グローバル設定との整合性

**現状**:
- `~/.claude/CLAUDE.md` にも同じ普遍原則がコピーされている
- my_skillsを基盤リポジトリとして使う場合、グローバル側との重複が発生

**課題**:
- どちらが正か曖昧
- 更新時に同期が必要

**対応予定**:
- [ ] グローバル側は最小限（または空）にする方針を明記
- [ ] インストール手順の見直し（README.md）

---

## 4. 品質チェック（qa-general）の自動発動

**現状**: 明示的に「品質チェックして」と依頼しないと発動しない

**課題**:
- Skill側に `recommended_subagents` として記載はあるが、推奨のみ
- フェーズ完了時に品質チェックを忘れる可能性がある

**方針**: 半自動
- Skill終了時（承認ポイント到達時）に「品質チェックしますか？」と確認
- ユーザーが承認したらqa-generalを呼び出す

**対応予定**:
- [ ] 各Skillの終了フローに品質チェック確認ステップを追加
- [ ] または、承認ポイント用の共通処理を作成

---

## 5. ディレクトリ構成の変更（Apps/ネスト管理）

**現状**: my_skills直下に基盤のみ、アプリは別リポジトリ想定

**課題**:
- my_skillsを開いて基盤を適用しつつ、複数アプリを管理したい
- 各アプリごとにPJ固有の.claude設定を持たせたい

**方針**: Apps/ディレクトリでネスト管理

```
my_skills/                      ← 基盤リポジトリ（VSCodeで開く）
├── .claude/                    ← 共通基盤（全Apps適用）
│   ├── CLAUDE.md
│   ├── skills/
│   ├── agents/
│   └── settings.json
├── Apps/                       ← 新規追加
│   ├── inquiry-platform/       ← アプリA
│   │   ├── .claude/            ← PJ固有設定（継承+上書き）
│   │   │   └── CLAUDE.md       ← コーディングルール等
│   │   └── src/
│   ├── another-project/        ← アプリB
│   │   ├── .claude/
│   │   └── src/
│   └── ...
├── Docs/
│   ├── foundation-improvements.md
│   └── requirements/
└── README.md
```

**メリット**:
- 1ワークスペースで複数PJ管理
- 共通基盤は自動適用、PJ固有ルールは各Apps/.claude/で上書き
- 要件定義書等もDocs/に集約可能

**対応予定**:
- [ ] Apps/ディレクトリ作成
- [ ] .gitignoreでApps/配下のnode_modules等を除外
- [ ] README.mdにネスト運用方法を追記
- [ ] Claude Codeのネスト時の.claude読み込み順序を検証

**検証事項**:
- Apps/project-a/.claude/CLAUDE.md は正しく継承+上書きされるか
- ネストが深い場合のコンテキスト読み込み挙動
