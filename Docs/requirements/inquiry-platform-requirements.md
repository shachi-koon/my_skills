# お問い合わせ管理基盤SaaS 要件定義書（たたき台）

## 1. プロジェクト概要

### 1.1 背景・課題
- 大手企業が複数サービスを運営しており、各サービスごとに問い合わせ管理機能が個別実装されている
- 問い合わせ対応の品質・進捗管理が統一されておらず、運用コストが高い
- サービス横断での問い合わせ傾向分析ができない
- **複数サービスにまたがって対応するオペレーターが、各サービスの管理画面を個別に確認する必要があり非効率**
- **各サービスが異なる認証技術を使用しており、統一的なユーザー体験が提供できていない**

### 1.2 目的
- 複数サービスの問い合わせを一元管理する基盤SaaSを提供
- 問い合わせ対応の標準化・効率化を実現
- ダッシュボードによる可視化で対応漏れを防止
- **サービス横断での対応状況把握を可能にする**

### 1.3 成功の定義（KPI）

#### システム指標（自動計測）

| 指標 | 目標値 | 計測方法 | 計測タイミング |
|------|--------|----------|---------------|
| システム稼働率 | 99.9%以上 | CloudWatch監視による月間稼働時間 / 月間総時間 | 月次 |
| API応答時間 | 95パーセンタイルで500ms以内 | CloudWatch Logsから自動集計 | 日次 |
| エラー率 | 1%未満 | 5xxエラー数 / 総リクエスト数をCloudWatchから集計 | 日次 |

#### 運用指標（参考値・テナント個別設定）

| 指標 | 参考目標 | 備考 |
|------|----------|------|
| 初回応答時間 | テナント設定の営業時間内で計測 | テナントごとに営業時間・目標値を設定可能 |
| 期限超過率 | テナント設定に依存 | カテゴリごとの期限設定に基づき計測 |

※ 本SaaSは各テナントが個別に運用していた問い合わせ管理を統合するため、統合前の運用状況がテナントごとに異なる。運用指標（初回応答時間、解決率等）は各テナントが個別に目標設定し、ダッシュボードで可視化する形とする。

### 1.4 ターゲット顧客
- 複数のWebサービス・アプリを運営する大手企業
- 既存の会員認証基盤を持つ企業

### 1.5 対応プラットフォーム
- **Webアプリケーションのみ**（モバイルはレスポンシブ対応）

## 2. ユーザー種別と権限（RBAC）

### 2.1 ロール一覧

| ロール | 所属 | 説明 |
|--------|------|------|
| エンドユーザー | - | 各サービスの利用者。問い合わせを行う |
| オペレーター | テナント | 担当サービスの問い合わせ対応担当者 |
| サービス管理者 | テナント | 担当サービスの全権限 + オペレーター管理 |
| テナント管理者 | テナント | テナント内全サービスの閲覧・管理、ユーザー管理 |
| システム管理者 | SaaS提供側 | テナント管理、システム設定、全体監視 |

### 2.2 権限マトリクス

| 機能 | エンドユーザー | オペレーター | サービス管理者 | テナント管理者 | システム管理者 |
|------|--------------|--------------|---------------|---------------|---------------|
| 問い合わせ投稿 | ○（自身） | - | - | - | - |
| 問い合わせ履歴閲覧 | ○（自身） | ○（担当サービス） | ○（担当サービス） | ○（全サービス） | ○（全テナント） |
| 問い合わせ回答 | - | ○（担当サービス） | ○（担当サービス） | ○（全サービス） | - |
| 担当者アサイン | - | ○（担当サービス） | ○（担当サービス） | ○（全サービス） | - |
| ダッシュボード閲覧 | - | ○（担当サービス） | ○（担当サービス） | ○（全サービス） | ○（全テナント） |
| オペレーター管理 | - | - | ○（担当サービス） | ○（全サービス） | - |
| サービス設定 | - | - | ○（担当サービス） | ○（全サービス） | - |
| テナント設定 | - | - | - | ○ | - |
| テナント管理 | - | - | - | - | ○ |
| システム設定 | - | - | - | - | ○ |

### 2.3 サービス別アクセス制御

- オペレーター/サービス管理者は **担当サービスのみ** 閲覧・操作可能
- テナント管理者は **テナント内全サービス** を閲覧・操作可能
- システム管理者は **全テナント** を閲覧可能（問い合わせ回答は不可）

## 3. スコープ

### 3.0 フェーズ1リリース範囲

**決定: 3.1スコープ内の全機能をフェーズ1でリリース**

| フェーズ | 範囲 |
|----------|------|
| **フェーズ1** | 3.1スコープ内の全機能（エンドユーザー機能、オペレーター/管理者機能、テナント管理者機能、システム管理者機能、認証認可、通知機能、マルチテナント対応） |
| **フェーズ2以降** | 3.2スコープ外の機能（AI自動応答、高度な分析機能等） |

### 3.1 スコープ内
1. **エンドユーザー向け機能**
   - 問い合わせフォーム（カテゴリ選択、添付ファイル対応）
   - 問い合わせ履歴一覧・詳細閲覧
   - **チャット形式での問い合わせ・回答履歴表示**
   - 回答通知（メール）
   - 元サービスへの戻りリンク
   - **SSO経由でのサービス識別（必須）**

2. **オペレーター/管理者向け機能**
   - 問い合わせ一覧（サービス別、ステータス別、期限別フィルタ）
   - **チャット形式での対応履歴表示**
   - 回答作成・送信
   - 内部メモ機能（ユーザー非表示）
   - **担当者アサイン（回答前でも可能）**
   - ダッシュボード（KPI表示、アラート）

3. **テナント管理者向け機能**
   - 全サービスの問い合わせ状況閲覧
   - オペレーター/サービス管理者アカウント管理
   - サービス登録・設定
   - テナント全体のダッシュボード

4. **システム管理者向け機能**
   - テナント（企業）管理
   - システム全体の監視ダッシュボード
   - システム設定

5. **認証認可**
   - エンドユーザー: **SSO必須**（Amazon Cognito Federation経由、SAML/OIDC対応）
   - サービス識別: **Cognito Groups** でサービスとユーザーを紐付け
   - 管理者/オペレーター: Amazon Cognito User Pools
   - 権限ベースのアクセス制御（RBAC）

6. **通知機能**
   - エンドユーザー向けメール通知
   - 管理者/オペレーター向けメール通知

7. **マルチテナント対応**
   - テナント（企業）単位でのデータ分離
   - サービス単位での問い合わせ識別

### 3.2 スコープ外
- チャットボット/AI自動応答
- 電話問い合わせ連携
- SNS連携（Twitter/LINE等）
- 既存問い合わせデータの移行ツール
- ネイティブモバイルアプリ
- 多言語対応（日本語のみ）
- **高度な分析機能（将来フェーズで検討）**

## 4. 機能要件

### 4.1 エンドユーザー向け機能

#### FR-U001: 問い合わせ投稿
| 項目 | 内容 |
|------|------|
| 概要 | ユーザーが問い合わせを投稿できる |
| 前提条件 | **SSO経由でのアクセス必須**（サービスは認証情報から自動識別） |
| 入力項目 | カテゴリ（必須）、件名（必須、100文字以内）、本文（必須、5000文字以内）、添付ファイル（任意、最大5件、1件あたり10MB以下） |
| 許可フォーマット | jpg, png, gif, pdf, doc, docx, xls, xlsx |
| AC | 1. 入力内容が保存され、問い合わせ番号が発行される<br>　**確認: 画面に問い合わせ番号表示 + InquiryテーブルにINSERT確認**<br>2. 投稿完了メールがユーザーに送信される<br>　**確認: SESログで送信成功を確認 + メール受信確認**<br>3. SSO認証時のサービス情報が問い合わせに自動紐付けされる<br>　**確認: Inquiry.service_idが認証元サービスと一致（DBクエリ）** |

#### FR-U002: 問い合わせ履歴閲覧
| 項目 | 内容 |
|------|------|
| 概要 | ユーザーが自身の問い合わせ履歴を閲覧できる |
| 表示項目 | 問い合わせ番号、サービス名、件名、ステータス、投稿日時、最終更新日時 |
| ソート | 投稿日時の降順（デフォルト） |
| ページネーション | 20件/ページ |
| AC | 1. 自身の問い合わせのみ表示される（他ユーザーの問い合わせは非表示）<br>　**確認: 別ユーザーでログインし、他者の問い合わせが表示されないことを画面確認**<br>2. ステータス、サービスでフィルタ可能<br>　**確認: 各フィルタ適用後、表示件数がDBクエリ結果と一致** |

#### FR-U003: 問い合わせ詳細閲覧（チャット形式）
| 項目 | 内容 |
|------|------|
| 概要 | 問い合わせの詳細と回答履歴をチャット形式で閲覧できる |
| 表示形式 | **チャットUI**（ユーザー投稿: 右側、オペレーター回答: 左側、時系列降順） |
| 表示項目 | 送信者（ユーザー/オペレーター表示名）、本文、添付ファイル、送信日時 |
| AC | 1. 回答があればチャット形式で時系列表示される<br>　**確認: 画面でメッセージが時系列降順に表示 + Message取得APIレスポンス確認**<br>2. 添付ファイルがダウンロード可能<br>　**確認: ダウンロードリンククリックでファイル取得成功（HTTPステータス200）**<br>3. 内部メモはユーザーに表示されない<br>　**確認: is_internal_memo=trueのMessageがAPIレスポンスに含まれないことを確認** |

#### FR-U004: 追加情報送信
| 項目 | 内容 |
|------|------|
| 概要 | 回答に対して追加情報を送信できる |
| 入力項目 | 本文（必須、5000文字以内）、添付ファイル（任意） |
| AC | 1. 送信内容がチャット履歴に追加される<br>　**確認: 画面にメッセージ表示 + MessageテーブルにINSERT確認**<br>2. 担当者に通知メールが送信される<br>　**確認: SESログで担当者宛メール送信成功を確認**<br>3. ステータスが「回答済み」の場合、「対応中」に自動変更される<br>　**確認: Inquiry.statusが'in_progress'に更新（DBクエリ）** |

#### FR-U005: 元サービスへの戻り
| 項目 | 内容 |
|------|------|
| 概要 | 問い合わせ画面から元のサービスに戻れる |
| 仕様 | サービスごとに設定された戻りURL（`return_url`パラメータ or サービス設定）にリダイレクト |
| AC | 1. 「戻る」ボタンクリックで元サービスに遷移する<br>　**確認: ボタンクリック後、Service.return_urlへリダイレクト（ブラウザURL確認）**<br>2. 戻りURLが未設定の場合はボタン非表示<br>　**確認: return_url=nullのサービスでボタンがDOM上に存在しないことを確認** |

### 4.2 オペレーター/管理者向け機能

#### FR-A001: 問い合わせ一覧
| 項目 | 内容 |
|------|------|
| 概要 | 問い合わせを一覧表示・検索できる |
| フィルタ条件 | サービス、ステータス、カテゴリ、担当者（未アサイン含む）、期限（超過/本日期限/期限間近/期限内）、投稿日範囲 |
| 検索 | 問い合わせ番号、件名、本文（部分一致） |
| ソート | 投稿日時、最終更新日時、期限（昇順/降順） |
| 視覚表示 | 期限超過: 赤、期限間近（24時間以内）: 黄、未アサイン: グレー背景<br>**※表示優先度: 期限超過（赤）> 期限間近（黄）> 未アサイン（グレー）** |
| AC | 1. オペレーター/サービス管理者は担当サービスの問い合わせのみ表示<br>　**確認: 担当外サービスの問い合わせがAPIレスポンスに含まれないことを確認**<br>2. テナント管理者は全サービスの問い合わせを表示<br>　**確認: テナント内全サービスの問い合わせがAPIレスポンスに含まれることを確認**<br>3. 未アサインの問い合わせが識別可能<br>　**確認: assigned_to=nullの行がグレー背景で表示（画面確認）** |

#### FR-A002: 問い合わせ詳細・対応（チャット形式）
| 項目 | 内容 |
|------|------|
| 概要 | 問い合わせの詳細確認と回答作成ができる |
| 表示形式 | **チャットUI**（ユーザー投稿: 左側、オペレーター回答: 右側、内部メモ: 別色背景で右側） |
| 表示項目 | 問い合わせ内容、ユーザー情報（氏名、メールアドレス）、対応履歴、内部メモ |
| 操作 | 回答作成、ステータス変更、担当者アサイン、内部メモ追加 |
| AC | 1. 回答送信でユーザーにメール通知される<br>　**確認: SESログでエンドユーザー宛メール送信成功を確認**<br>2. 内部メモはユーザーに表示されない（管理者のみ閲覧可）<br>　**確認: エンドユーザー向けAPIレスポンスにis_internal_memo=trueが含まれないことを確認**<br>3. ユーザー投稿とオペレーター回答が視覚的に区別される<br>　**確認: 画面でユーザー投稿=左、オペレーター回答=右に配置されていることを目視確認** |

#### FR-A003: 担当者アサイン
| 項目 | 内容 |
|------|------|
| 概要 | 問い合わせに担当者を割り当てる |
| タイミング | **回答前でもアサイン可能**（先に担当者だけ決めるユースケースに対応） |
| 対象者 | 該当サービスを担当するオペレーター/サービス管理者 |
| AC | 1. アサイン時に担当者にメール通知される<br>　**確認: SESログでアサインされた担当者宛メール送信成功を確認**<br>2. アサイン履歴が記録される（誰が、いつ、誰にアサインしたか）<br>　**確認: 監査ログテーブルにアサイン操作が記録されていることをDBクエリで確認**<br>3. 未回答でもアサインのみ可能<br>　**確認: Messageが0件のInquiryに対してassigned_to更新が成功（API 200返却）** |

#### FR-A004: ステータス管理
| 項目 | 内容 |
|------|------|
| ステータス | 未対応、対応中、回答済み、完了、保留 |
| 自動遷移 | 担当者アサイン時: 未対応→対応中<br>回答送信時: →回答済み<br>ユーザー追加情報送信時: 回答済み→対応中 |
| 自動完了 | **回答済み状態で72時間経過**: ユーザーに「追加情報がなければ完了とします」確認メール送信<br>**確認メール送信後1週間経過かつ追加情報なし**: 自動で「完了」に遷移し、「追加のご連絡がなかったため終了しました」メール送信 |
| 自動完了対象外 | **保留ステータスは自動完了の対象外**（オペレーターが手動で保留解除するまで状態を維持） |
| 手動変更 | 完了、保留への変更は手動でも可能 |
| ステータス戻し | **完了から任意のステータスへ変更可能**: オペレーターが手動で変更可能（完了→対応中、完了→保留等）<br>・対応中への変更時: ユーザーに「対応を再開しました」通知メール送信<br>・保留/未対応への変更時: **通知なし**（内部運用のため） |
| AC | 1. ステータス変更履歴が記録される（誰が、いつ、何に変更したか）<br>　**確認: 監査ログテーブルにステータス変更が記録されていることをDBクエリで確認**<br>2. 自動遷移が正しく動作する<br>　**確認: アサイン時→対応中、回答送信時→回答済み、追加情報送信時→対応中への遷移をそれぞれDB確認**<br>3. 自動完了フローが動作する<br>　**確認: 回答済み+72時間後に確認メール送信（SESログ）、さらに1週間後にstatus='completed'に更新（DBクエリ）+ 完了通知メール送信（SESログ）**<br>4. 完了→対応中への戻し時に通知メールが送信される<br>　**確認: SESログでエンドユーザー宛「対応再開」メール送信成功を確認**<br>5. 保留ステータスは自動完了の対象外である<br>　**確認: 保留状態で72時間以上経過しても確認メールが送信されない（SESログに該当送信なし）** |

#### FR-A005: 対応期限管理
| 項目 | 内容 |
|------|------|
| 概要 | 問い合わせに対応期限を設定できる |
| デフォルト期限 | カテゴリごとに設定可能（例: 一般問い合わせ=3営業日、緊急=1営業日） |
| 期限間近 | 期限24時間以内を「期限間近」として識別 |
| AC | 1. 期限超過の問い合わせが一覧で赤色表示<br>　**確認: deadline < 現在時刻のInquiryが赤色背景で表示（画面目視 + CSSクラス確認）**<br>2. 期限間近の問い合わせが一覧で黄色表示<br>　**確認: 期限24時間以内のInquiryが黄色背景で表示（画面目視 + CSSクラス確認）**<br>3. 期限超過時にアラートメール送信（担当者 + サービス管理者）<br>　**確認: SESログで担当者・サービス管理者宛のメール送信成功を確認** |

#### FR-A006: ダッシュボード
| 項目 | 内容 |
|------|------|
| **対応状況サマリ** | |
| - 未対応件数 | ステータスが「未対応」の件数 |
| - 対応中件数 | ステータスが「対応中」の件数 |
| - 回答済み（完了待ち）件数 | ステータスが「回答済み」で完了していない件数 |
| - 保留件数 | ステータスが「保留」の件数 |
| **アラート表示** | |
| - 期限超過件数 | 期限を過ぎた未完了問い合わせ件数（赤色強調） |
| - 期限間近件数 | 期限24時間以内の未完了問い合わせ件数（黄色強調） |
| - 長期滞留件数 | 72時間以上未更新の問い合わせ件数 |
| - 未アサイン件数 | 担当者が未設定の問い合わせ件数 |
| **分析指標** | |
| - サービス別問い合わせ数 | 棒グラフ/円グラフ |
| - カテゴリ別問い合わせ数 | 棒グラフ/円グラフ |
| - 平均初回応答時間 | 投稿から最初の回答までの平均時間 |
| - 平均解決時間 | 投稿から完了までの平均時間 |

## 6. 認証認可要件

### 6.1 エンドユーザー認証（SSO必須）

| 項目 | 内容 |
|------|------|
| 認証基盤 | Amazon Cognito User Pools + Federation |
| 認証方式 | **SSO連携必須**（各サービスのIdP経由でのみアクセス可能） |
| 対応プロトコル | SAML 2.0、OpenID Connect 1.0 |
| セッション管理 | JWTトークン（有効期限: 1時間、リフレッシュトークン: 7日） |
| ユーザー情報取得 | IdPから属性（氏名、メールアドレス等）をマッピング |
| サービス識別 | **Cognito Groups** でサービスIDを紐付け（どのサービス経由かを識別） |

#### 設計方針
- 各サービスは独自の認証基盤（IdP）を持っている前提
- 認証基盤がバラバラでも、Cognito Federationで統合することで本SaaSへのアクセスを統一
- **直接アクセスは不可**（各サービス経由でのSSO認証が必須）

#### SSO連携フロー
```
1. ユーザーがサービス内「お問い合わせ」リンクをクリック
2. サービスからCognitoへリダイレクト（IdP識別子を指定）
3. Cognitoが該当サービスのIdPへリダイレクト
4. IdPで認証（既にログイン済みの場合は自動認証）
5. SAMLアサーション or OIDCトークンをCognitoに返却
6. CognitoでJWTトークン発行（サービスIDをCognito Groupに設定）
7. 問い合わせ画面を表示（ユーザー情報・サービス情報は自動取得）
```

#### Cognito Groups によるサービス紐付け
```
- グループ名: service_{service_code}（例: service_ec_site, service_member_app）
- SSO認証成功時に、該当サービスのグループにユーザーを自動追加
- JWTの cognito:groups クレームでサービス識別
- 1ユーザーが複数サービスを利用する場合、複数グループに所属
```

#### IdP設定のCI/CD化
- サービス登録時、Cognito Federation設定をAWS CDK（CloudFormation）で自動生成
- GitHub Actionsで設定変更をデプロイ

### 6.2 管理者/オペレーター認証

| 項目 | 内容 |
|------|------|
| 認証基盤 | Amazon Cognito User Pools |
| 認証方式 | メール + パスワード |
| MFA | TOTP必須（Google Authenticator等） |
| パスワードポリシー | 最小12文字、大文字・小文字・数字・記号を各1文字以上、90日で有効期限切れ |
| セッション | 8時間（無操作30分でタイムアウト） |
| ロックアウト | 5回連続失敗で30分ロック |

### 6.3 権限制御

- Cognito Groups でロール（オペレーター、サービス管理者、テナント管理者、システム管理者）を管理
- カスタム属性で担当サービスIDを保持
- APIアクセス時にJWTからロール・担当サービスを検証

## 10. データモデル（概要）

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   Tenant    │────<│   Service   │────<│  Category   │
│  (テナント)  │     │ (サービス)   │     │(カテゴリ)   │
└─────────────┘     └─────────────┘     └─────────────┘
       │                   │
       │                   │
       ▼                   ▼
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│ AdminUser   │     │   Inquiry   │────<│   Message   │
│(管理者/OP)  │────<│ (問い合わせ) │     │ (メッセージ) │
└─────────────┘     └─────────────┘     └─────────────┘
       │                   │                   │
       │                   │                   ▼
       │                   │            ┌─────────────┐
       │                   └───────────>│ Attachment  │
       │                                │ (添付ファイル)│
       │                                └─────────────┘
       │
       ▼
┌─────────────┐
│ ServiceRole │
│(サービス権限)│
└─────────────┘
```

### 主要エンティティ

| エンティティ | 主要属性 |
|-------------|---------|
| Tenant | id, name, plan, status, created_at |
| Service | id, tenant_id, name, service_code, sso_config, return_url, cognito_group_name |
| Category | id, service_id, name, default_deadline_hours, sort_order |
| AdminUser | id, tenant_id, cognito_sub, email, name, role, status |
| ServiceRole | id, admin_user_id, service_id（オペレーターの担当サービス管理） |
| EndUser | id, tenant_id, cognito_sub, email, name, idp_user_id（SSO認証時のユーザー情報） |
| Inquiry | id, service_id, end_user_id, category_id, subject, status, deadline, assigned_to |
| Message | id, inquiry_id, sender_type, sender_id, body, is_internal_memo, created_at |
| Attachment | id, message_id, filename, s3_key, size, content_type |
