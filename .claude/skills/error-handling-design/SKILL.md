# エラーハンドリング設計

## 概要
実装前にエラーハンドリング方針を決定し、一貫した対応を実現する。

## 設計項目

### 1. エラー分類
| 分類 | 説明 | 例 |
|------|------|-----|
| **業務エラー** | 想定内のエラー | バリデーションエラー、認証エラー |
| **システムエラー** | 想定外のエラー | DB接続エラー、メモリ不足 |
| **外部エラー** | 外部依存のエラー | API障害、ネットワークエラー |

### 2. タイムアウト設計

| 処理種別 | デフォルト値 | 備考 |
|---------|-------------|------|
| HTTP API呼び出し | 30秒 | 外部APIは要個別設定 |
| DB接続 | 5秒 | コネクションプール設定 |
| DBクエリ | 30秒 | 重いクエリは要個別設定 |
| ファイルI/O | 60秒 | サイズに応じて調整 |
| バッチ処理 | 処理依存 | 必ず上限を設定 |

### 3. リトライ戦略

#### リトライ対象
| エラー種別 | リトライ | 理由 |
|-----------|---------|------|
| ネットワーク一時エラー | ○ | 一時的な障害 |
| 5xx系エラー | ○ | サーバー側の一時障害 |
| タイムアウト | ○ | 負荷による遅延 |
| 4xx系エラー | × | クライアント側の問題 |
| バリデーションエラー | × | データの問題 |
| 認証エラー | × | 認証情報の問題 |

#### リトライパラメータ
```
最大リトライ回数: 3回
初回待機時間: 1秒
バックオフ係数: 2（Exponential Backoff）
最大待機時間: 30秒

待機時間の例:
  1回目失敗 → 1秒待機
  2回目失敗 → 2秒待機
  3回目失敗 → 4秒待機
  4回目失敗 → 処理中断
```

### 4. ログ方針

#### ログレベル
| レベル | 用途 | 例 |
|--------|------|-----|
| ERROR | 即座に対応が必要 | 未処理例外、データ不整合 |
| WARN | 注意が必要 | リトライ発生、性能劣化 |
| INFO | 正常な業務イベント | 処理開始/完了、状態変更 |
| DEBUG | 開発時のデバッグ情報 | 変数値、分岐条件 |

#### ログ出力項目
```
必須項目:
- タイムスタンプ（ISO 8601形式）
- ログレベル
- リクエストID / トレースID
- エラーメッセージ
- スタックトレース（ERROR時）

推奨項目:
- ユーザーID（該当する場合）
- 処理名・メソッド名
- 入力パラメータ（機密情報マスク済み）
- 処理時間
```

### 5. ユーザーへのエラーメッセージ

| 内部エラー | ユーザー向けメッセージ |
|-----------|---------------------|
| NullPointerException | システムエラーが発生しました |
| ConnectionTimeout | 接続がタイムアウトしました。しばらく後に再試行してください |
| ValidationError | 入力内容を確認してください: [具体的な項目] |
| AuthenticationError | 認証に失敗しました。ログイン情報を確認してください |

**原則:** 内部実装の詳細はユーザーに見せない
