# テスト検証

## 概要
実装完了後にテストを作成し、実装が仕様通りであることを検証する。

## 基本原則

### SDDにおけるテストの位置づけ
```
仕様 → 実装 → テスト（検証）
              ↑ ここ
```

- テストは「実装の検証手段」
- テストを通すための実装改修は**絶対禁止**
- テストが失敗したら実装を見直す（テストを変えない）

### 目標
- カバレッジ: 80%以上
- 正常系・異常系・境界値をカバー

## テスト種別

### 1. 単体テスト（Unit Test）
| 対象 | 関数・メソッド単位 |
|------|------------------|
| 目的 | ロジックの正しさを検証 |
| 依存 | モック化 |
| 実行速度 | 高速 |

### 2. 結合テスト（Integration Test）
| 対象 | モジュール間連携 |
|------|-----------------|
| 目的 | 連携の正しさを検証 |
| 依存 | 実際のDB/API（テスト用） |
| 実行速度 | 中速 |

### 3. E2Eテスト（End-to-End Test）
| 対象 | システム全体 |
|------|-------------|
| 目的 | ユーザーシナリオの検証 |
| 依存 | 実環境に近い構成 |
| 実行速度 | 低速 |

## テスト設計

### テストケースの観点

#### 正常系
- 典型的な入力での動作
- 仕様通りの出力

#### 異常系
- 不正入力（null, 空文字, 不正形式）
- 認証エラー
- 権限エラー
- 外部依存エラー（DBエラー、APIエラー）

#### 境界値
- 最小値・最大値
- 境界の直前・直後
- 空配列・1要素配列・多要素配列

### テストケース設計テンプレート
```markdown
## テストケース: [機能名]

### 正常系
| ID | 入力 | 期待結果 | 確認観点 |
|----|------|---------|---------|
| N001 | | | |

### 異常系
| ID | 入力 | 期待結果 | 確認観点 |
|----|------|---------|---------|
| E001 | | | |

### 境界値
| ID | 入力 | 期待結果 | 確認観点 |
|----|------|---------|---------|
| B001 | | | |
```

## テストコード規約

### 命名規約
```typescript
// パターン: test_[対象]_[条件]_[期待結果]
test_login_validCredentials_returnsToken()
test_login_invalidPassword_throwsAuthError()
test_getUsers_emptyDatabase_returnsEmptyArray()
```

### 構造（AAA パターン）
```typescript
test('ログイン成功時にトークンを返す', () => {
  // Arrange（準備）
  const email = 'test@example.com';
  const password = 'validPassword123';

  // Act（実行）
  const result = authService.login(email, password);

  // Assert（検証）
  expect(result.token).toBeDefined();
  expect(result.expiresIn).toBe(3600);
});
```

### モックの使用方針
| 対象 | モック化 | 理由 |
|------|---------|------|
| 外部API | ○ | テスト安定性 |
| DB（単体テスト） | ○ | 高速化 |
| DB（結合テスト） | × | 実際の動作検証 |
| 時刻 | ○ | 再現性確保 |
| ランダム値 | ○ | 再現性確保 |

## 実行手順

### Step 1: テストケース設計
1. 仕様書からテスト観点を抽出
2. 正常系・異常系・境界値を洗い出す
3. テストケース一覧を作成

### Step 2: テストコード作成
1. テストファイルを作成
2. AAAパターンで記述
3. モックを適切に設定

### Step 3: 実行・検証
```bash
# 全テスト実行
npm run test

# カバレッジ確認
npm run test:coverage

# 特定ファイルのみ
npm run test -- path/to/file.test.ts
```

### Step 4: カバレッジ確認
- 目標: 80%以上
- 未カバー部分を確認し、追加テストを検討

## チェックリスト
- [ ] 正常系をカバーしているか
- [ ] 異常系をカバーしているか
- [ ] 境界値をカバーしているか
- [ ] カバレッジ80%以上か
- [ ] テストが独立しているか（他テストに依存しない）
- [ ] テストが再現可能か（何度実行しても同じ結果）
- [ ] **テストを通すための実装改修をしていないか**
