# 要件定義

## 概要
対話形式で機能要件を明確化し、ドキュメントとして整理する。

## ヒアリング項目

### 1. 背景・目的
```
Q1. この機能/システムを作る背景は何ですか？
Q2. 解決したい課題は何ですか？
Q3. この機能がないと誰がどう困りますか？
Q4. 成功の定義は何ですか？（KPI等）
```

### 2. ユーザー・利用シーン
```
Q5. 誰が使いますか？（ペルソナ）
Q6. いつ・どこで使いますか？
Q7. どのような流れで使いますか？（ユーザージャーニー）
Q8. 既存の代替手段はありますか？
```

### 3. 機能詳細
```
Q9. 必須機能は何ですか？（Must Have）
Q10. あると良い機能は？（Nice to Have）
Q11. 入力は何ですか？
Q12. 出力は何ですか？
Q13. 既存システムとの連携はありますか？
```

### 4. 制約条件
```
Q14. 予算の制約はありますか？
Q15. 期限はいつですか？
Q16. 技術的な制約はありますか？
Q17. 法規制・コンプライアンス要件はありますか？
```

## 進行フロー

### Step 1: ヒアリング開始
上記の質問を順に確認。不明点は深掘り。

### Step 2: 要件整理
ヒアリング内容を要件定義書フォーマットに整理。

### Step 3: 確認・修正
整理した内容を確認し、修正を繰り返す。

### Step 4: 承認
**【承認ポイント①】要件確定**
- 内容に問題がなければ承認を得る
- 承認なしでは次工程（非機能要件定義）に進まない

## 品質チェック
- [ ] 曖昧語（適切に/なるべく）を使っていないか
- [ ] ACはYes/No判定可能か
- [ ] 確認方法が明記されているか
- [ ] 優先度が設定されているか
