# コードレビュー

## 概要
一貫した観点でコードをレビューし、問題点と改善案を提示する。

## レビュー観点

### 1. セキュリティ
- [ ] SQLインジェクション対策
- [ ] XSS対策
- [ ] 認証・認可の適切な実装
- [ ] 機密情報のハードコーディングなし
- [ ] 入力値のバリデーション

### 2. 性能
- [ ] N+1クエリの有無
- [ ] 不要なループ・再計算
- [ ] 適切なインデックス設計
- [ ] メモリリークの可能性
- [ ] 非同期処理の適切な使用

### 3. 保守性
- [ ] 命名の明確さ（変数、関数、クラス）
- [ ] 単一責任の原則
- [ ] 適切な抽象化レベル
- [ ] コメントの適切さ（Why > What）
- [ ] マジックナンバーの排除

### 4. エラーハンドリング
- [ ] 例外の適切なキャッチと処理
- [ ] エラーメッセージの明確さ
- [ ] リトライ・フォールバックの考慮
- [ ] ログ出力の適切さ

### 5. テスト
- [ ] テストカバレッジ（80%以上目標）
- [ ] 正常系・異常系・境界値
- [ ] テストの独立性
- [ ] モックの適切な使用

## レビュー手順

### Step 1: 全体把握
1. PRの目的・背景を確認
2. 変更ファイル一覧を確認
3. 影響範囲を把握

### Step 2: 詳細レビュー
1. 上記観点でコードをチェック
2. 問題点を記録
3. 改善案を検討

### Step 3: フィードバック作成

## 出力フォーマット

```markdown
## レビュー結果

### サマリ
- 対象: PR #XXX
- 変更規模: X files, +Y/-Z lines
- 総合評価: 🟢 LGTM / 🟡 要修正 / 🔴 要再設計

### 指摘事項

#### 🔴 Critical（修正必須）
| ファイル | 行 | 問題 | 改善案 |
|---------|-----|------|--------|
| | | | |

#### 🟡 Warning（修正推奨）
| ファイル | 行 | 問題 | 改善案 |
|---------|-----|------|--------|
| | | | |

#### 🟢 Info（提案）
| ファイル | 行 | 内容 |
|---------|-----|------|
| | | |

### Good Points
- ...
```

## 注意事項
- 指摘は具体的に（行番号、コード例を含める）
- 改善案を必ず併記
- 良い点も伝える
