# 仕様駆動開発ワークフロー

## 概要
仕様を先に固め、実装し、テストで検証する開発フロー。

## ワークフロー

### Step 1: 仕様確認
1. 要件定義書・設計書を確認
2. 不明点があれば質問（実装前に解消必須）
3. スコープ内/スコープ外を再確認

**確認項目:**
- [ ] 機能要件が明確か
- [ ] 非機能要件（性能、エラー処理）が定義されているか
- [ ] 境界条件が明記されているか

### Step 2: 実装計画
1. タスクを分解（1タスク=1PR単位）
2. 各タスクのDone条件を明記
3. 依存関係を整理

**出力:** タスクリスト（チケット番号付き）

### Step 3: 実装
1. チケット単位で実装
2. コミットメッセージにチケット番号を含める
3. 変更経緯をチケットに記録

**コミット規約:**
```
<type>: <subject> #<ticket-number>

例: feat: ログイン機能追加 #123
```

### Step 4: テスト作成（実装後）
1. 実装したコードに対してテストを作成
2. 正常系・異常系・境界値をカバー
3. カバレッジ80%以上を目標

**禁止事項:** テストを通すための実装改修は絶対禁止

### Step 5: レビュー依頼
1. PRを作成
2. 変更内容・影響範囲を明記
3. レビュー観点を提示

## 承認ポイント
- 仕様確認後 → 実装開始の承認
- 実装完了後 → レビュー・マージの承認

**承認なしでは次に進まないこと。**
