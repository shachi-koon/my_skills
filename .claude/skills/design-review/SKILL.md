# 設計レビュー

## 概要
設計の選択肢を比較検討し、意思決定を支援する。最終判断は人が行う。

## レビュー観点

### 1. 要件との整合性
- [ ] 機能要件を満たしているか
- [ ] 非機能要件（性能、可用性）を満たせるか
- [ ] スコープ内に収まっているか

### 2. アーキテクチャ
- [ ] 選択したアーキテクチャは適切か
- [ ] 将来の拡張性は考慮されているか
- [ ] 技術的負債になりそうな箇所はないか

### 3. データ設計
- [ ] データモデルは正規化されているか（または意図的な非正規化か）
- [ ] インデックス設計は適切か
- [ ] データ量増加時のスケーラビリティは考慮されているか

### 4. API設計
- [ ] RESTful原則に従っているか（該当する場合）
- [ ] エラーレスポンスは統一されているか
- [ ] バージョニング戦略はあるか

### 5. セキュリティ
- [ ] 認証・認可の設計は適切か
- [ ] 機密データの扱いは適切か
- [ ] 入力値の検証は考慮されているか

### 6. 運用性
- [ ] ログ設計は適切か
- [ ] 監視・アラート設計は考慮されているか
- [ ] デプロイ・切り戻し手順は考慮されているか

### 7. テスト容易性
- [ ] テストしやすい設計になっているか
- [ ] 依存関係の注入は考慮されているか

## 進行フロー

### Step 1: 設計書の確認
設計書を読み込み、全体像を把握。

### Step 2: 観点別レビュー
上記観点でチェック。問題点を記録。

### Step 3: 代替案の検討
問題がある場合、代替案を検討。

### Step 4: フィードバック
問題点と改善案を整理して提示。

### Step 5: 修正・再レビュー
修正後、再度レビュー。

### Step 6: 承認
**【承認ポイント④】設計確定**
- 重大な問題がないことを確認
- 承認なしでは次工程（タスク分解）に進まない
