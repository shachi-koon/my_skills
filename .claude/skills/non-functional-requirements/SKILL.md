# 非機能要件定義

## 概要
性能・可用性・セキュリティ等の非機能要件の「最低ライン」を先に決め、手戻りを防ぐ。

## ヒアリング項目

### 1. 性能要件
```
Q1. 想定同時アクセス数は？（ピーク時）
Q2. 許容レスポンスタイムは？（95パーセンタイル）
Q3. 1日あたりのデータ量は？
Q4. データ保持期間は？
Q5. バッチ処理の許容時間は？
```

### 2. 可用性要件
```
Q6. 目標�kind稼働率は？（99.9%など）
Q7. 許容ダウンタイムは？（月/年あたり）
Q8. 計画メンテナンス時間帯は？
Q9. 障害時の復旧目標時間（RTO）は？
Q10. データ損失許容範囲（RPO）は？
```

### 3. セキュリティ要件
```
Q11. 扱うデータの機微度は？（個人情報、決済情報など）
Q12. 認証方式は？（ID/PW、SSO、MFAなど）
Q13. 認可の粒度は？（ロールベース、属性ベースなど）
Q14. 監査ログの要件は？
Q15. 外部からのアクセス制限は？
```

### 4. 運用・保守要件
```
Q16. 監視項目は？
Q17. アラート通知先は？
Q18. ログの保持期間は？
Q19. バックアップ頻度は？
Q20. 切り戻し手順は必要か？
```

## 最低ラインの目安

### 性能（参考値）
| 項目 | 小規模 | 中規模 | 大規模 |
|------|--------|--------|--------|
| 同時接続数 | ~100 | ~1,000 | 10,000+ |
| レスポンス | 3秒以内 | 1秒以内 | 500ms以内 |
| スループット | ~10 req/s | ~100 req/s | 1,000+ req/s |

### 可用性（参考値）
| 稼働率 | 年間ダウンタイム | 用途 |
|--------|----------------|------|
| 99% | 約3.65日 | 社内システム |
| 99.9% | 約8.76時間 | 一般的なWebサービス |
| 99.99% | 約52分 | ミッションクリティカル |

### セキュリティ（データ機微度別）
| 機微度 | 例 | 最低要件 |
|--------|-----|---------|
| 低 | 公開情報 | HTTPS、基本認証 |
| 中 | 会員情報 | 暗号化保存、MFA推奨 |
| 高 | 決済・医療情報 | MFA必須、監査ログ、暗号化必須 |

## 進行フロー

### Step 1: ヒアリング
各カテゴリの質問を確認。

### Step 2: 最低ラインの設定
「これ以上は許容できない」ラインを明確化。

### Step 3: 文書化
非機能要件書として整理。

### Step 4: 承認
**【承認ポイント②】非機能要件確定**
- 承認なしでは次工程（スコープ定義）に進まない

## 注意事項
- 「最低ライン」は妥協点ではなく「これ以下は許容不可」の基準
- 目標値と最低ラインは分けて記載
- 測定方法も併記（後で検証できるように）
