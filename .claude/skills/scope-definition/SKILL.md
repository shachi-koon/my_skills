# スコープ定義

## 概要
「やること」と「やらないこと」を明確に分け、後出し要求を防ぐ。

## ヒアリング項目

### 1. スコープ内の確認
```
Q1. 今回必ず実装する機能は何ですか？
Q2. 対象ユーザーは誰ですか？
Q3. 対象デバイス/プラットフォームは？
Q4. 対象データの範囲は？
Q5. 連携する外部システムは？
```

### 2. スコープ外の確認
```
Q6. 今回対応しない機能は何ですか？
Q7. 対象外のユーザーは？
Q8. 対象外のデバイス/プラットフォームは？
Q9. 次フェーズ以降に回す機能は？
Q10. 明示的に「やらない」と決めたことは？
```

### 3. 境界の確認
```
Q11. 判断に迷う「グレーゾーン」はありますか？
Q12. 「〇〇の場合はスコープ外」という条件付きのものは？
Q13. ステークホルダー間で認識がずれている点は？
```

## 進行フロー

### Step 1: スコープ内の列挙
やることを具体的にリストアップ。

### Step 2: スコープ外の列挙
やらないことを具体的にリストアップ。

### Step 3: 境界の明確化
グレーゾーンを議論し、白黒つける。

### Step 4: 文書化・合意
スコープ定義書として整理。

### Step 5: 承認
**【承認ポイント③】スコープ確定**
- 承認なしでは次工程（設計）に進まない
- スコープ変更は変更管理プロセスを通す

## 注意事項
- 「スコープ外」は「やらない」ではなく「今回はやらない」
- 次フェーズ対応予定のものは明記
- 曖昧な表現（「基本的には」「原則として」）を避ける
- ステークホルダー全員の合意を得る
