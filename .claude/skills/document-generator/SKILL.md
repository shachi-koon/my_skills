# ドキュメント生成

## 概要
一貫したフォーマットで高品質なドキュメントを生成する。

## 対応ドキュメント種別

### 1. 要件定義書
```markdown
# 要件定義書: [機能名]

## 1. 概要
### 1.1 目的
### 1.2 背景
### 1.3 対象ユーザー

## 2. 機能要件
### 2.1 機能一覧
| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|

### 2.2 機能詳細
#### FR-001: [機能名]
- 説明:
- 入力:
- 出力:
- 受入条件（AC）:
  - [ ] [Yes/No判定可能な条件] - 確認方法: [画面/API/ログ]

## 3. 非機能要件
### 3.1 性能
### 3.2 可用性
### 3.3 セキュリティ

## 4. スコープ
### 4.1 スコープ内
### 4.2 スコープ外

## 5. 未決事項
| ID | 内容 | 責任者 | 期限 | 決定予定の承認ポイント |
|----|------|--------|------|----------------------|
```

### 2. 設計書
```markdown
# 設計書: [機能名]

## 1. 概要
### 1.1 対象機能
### 1.2 関連要件

## 2. アーキテクチャ
### 2.1 全体構成図
### 2.2 採用パターン
### 2.3 選定理由

## 3. 詳細設計
### 3.1 クラス図 / モジュール構成
### 3.2 シーケンス図
### 3.3 データモデル

## 4. エラーハンドリング
| エラー種別 | 発生条件 | 対応方法 | リトライ | ログ |
|-----------|---------|---------|---------|------|

## 5. 非機能設計
### 5.1 性能設計
### 5.2 監視・ログ設計
### 5.3 セキュリティ設計
```

### 3. APIリファレンス
```markdown
# API リファレンス

## エンドポイント一覧
| メソッド | パス | 説明 |
|---------|------|------|

## エンドポイント詳細

### [POST] /api/v1/xxx

#### 概要
[説明]

#### リクエスト
**Headers**
| ヘッダー | 必須 | 説明 |
|---------|------|------|

**Body**
```json
{
  "field": "type - 説明"
}
```

#### レスポンス
**成功時 (200)**
```json
{
  "field": "type - 説明"
}
```

**エラー時**
| コード | 説明 | 対応 |
|--------|------|------|

#### 例
**リクエスト例**
```bash
curl -X POST ...
```

**レスポンス例**
```json
{ ... }
```
```

## 生成プロセス

### Step 1: 種別の確認
どのドキュメントを生成するか確認。

### Step 2: 情報収集
必要な情報をヒアリングまたはコードから抽出。

### Step 3: ドラフト作成
テンプレートに沿って初稿を作成。

### Step 4: レビュー・修正
内容の確認と修正を繰り返す。

## 品質チェックリスト
- [ ] 曖昧語（適切に/なるべく）を使っていないか
- [ ] ACはYes/No判定可能か
- [ ] スコープ内/外が明記されているか
- [ ] 未決事項に責任者・期限があるか
- [ ] 3年目エンジニアが読んで理解できるか
