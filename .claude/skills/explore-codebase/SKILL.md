# コードベース調査

## 概要
効率的にコードベースを理解し、必要な情報を抽出する。

## 調査パターン

### パターン1: 全体構造の把握
新規参画時やプロジェクト理解に使用。

```
1. ディレクトリ構造を確認
2. package.json / requirements.txt 等で依存関係を把握
3. エントリーポイントを特定
4. 主要なモジュール・レイヤーを理解
```

**出力:** 構造図、主要コンポーネント一覧

### パターン2: 機能の実装箇所特定
特定機能の修正・理解に使用。

```
1. 機能名・キーワードでGrep
2. 関連ファイルを特定
3. 呼び出し関係を追跡
4. データフローを整理
```

**出力:** 関連ファイル一覧、呼び出しフロー図

### パターン3: 影響範囲調査
修正時の影響範囲把握に使用。

```
1. 対象ファイル・関数を特定
2. 参照元を検索（Grep）
3. 依存関係を追跡
4. テストファイルを確認
```

**出力:** 影響範囲リスト、関連テスト一覧

### パターン4: パターン・規約の発見
既存の実装パターンを理解するのに使用。

```
1. 類似機能の実装を検索
2. 共通パターンを抽出
3. 命名規約・ディレクトリ規約を把握
4. エラーハンドリングパターンを確認
```

**出力:** 実装パターン集、規約まとめ

## 調査手順

### Step 1: 目的の明確化
何を知りたいのか、なぜ知りたいのかを確認。

### Step 2: 調査実行
適切なパターンを選択して調査。

### Step 3: 結果の整理
構造化された形式で整理。
