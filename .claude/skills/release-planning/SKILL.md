# リリース計画

## 概要
リリース手順と切り戻し手順をセットで策定し、安全なリリースを実現する。

## 基本原則

### 手順と切り戻しはセット
- リリース手順だけでは不完全
- 切り戻し手順がないリリースは許可しない
- 切り戻し判断基準も事前に決める

### 実行可能なレベルで記述
- 「〇〇を確認する」ではなく「〇〇コマンドを実行して△△を確認する」
- コマンド、URL、確認値を具体的に記載

## ヒアリング項目

### 1. リリース内容
```
Q1. 何をリリースしますか？
Q2. 影響範囲は？
Q3. リリース予定日時は？
Q4. メンテナンス時間は必要ですか？
```

### 2. 前提条件
```
Q5. リリース前に完了しているべきことは？
Q6. 必要な承認は？
Q7. 関係者への事前連絡は必要ですか？
```

### 3. リリース手順
```
Q8. デプロイ方法は？（CI/CD、手動など）
Q9. DB マイグレーションはありますか？
Q10. 設定変更はありますか？
Q11. 確認項目は？
```

### 4. 切り戻し
```
Q12. 切り戻しが必要になる条件は？
Q13. 切り戻し手順は？
Q14. データの切り戻しは可能ですか？
Q15. 切り戻しの判断者は誰ですか？
```

### 5. 監視・連絡
```
Q16. リリース後の監視項目は？
Q17. 障害時の連絡先は？
Q18. エスカレーションルートは？
```

## 進行フロー

### Step 1: リリース内容の確認
何をリリースするか、影響範囲を明確化。

### Step 2: 手順の策定
リリース手順を具体的に記述。

### Step 3: 切り戻し手順の策定
切り戻し条件と手順を具体的に記述。

### Step 4: レビュー
手順の妥当性を確認。

### Step 5: 承認
**【承認ポイント⑦】リリース承認**
- 手順と切り戻しがセットで承認される
- 承認なしではリリース実施不可
